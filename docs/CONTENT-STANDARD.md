# 内容标准（CONTENT-STANDARD）

> 本文件把 `ARCHITECTURE.md` 与 `packages/tooling/AGENTS.md` 的写作要求，落成**可验收的数字**。
> 派发写作任务、审核章节、判定"能不能合入"都以本文件为准。
> 适用范围：`apps/*/docs/**/*.md` 的全部正文章节（`index.md`、`SUMMARY.md`、附录速查表除外）。

## 0. 一句话标准

**一章 = 一个能独立教人的单元**：读者读完能说清"它解决什么问题、怎么算、怎么选、怎么错、怎么验"，并且**每个数字都能被复算、每条结论都有出处**。

## 1. 硬性门槛（不满足即退回，不讨论）

| # | 门槛 | 判定方式 |
|---|---|---|
| H1 | **正文中文字数 ≥ 4,500**（工程实践/测量类 ≥ 3,500；速查/附录类不适用本表） | 统计 CJK 字符（脚本计数） |
| H2 | **11 个模块齐全且顺序一致**（见 §2） | 人工核对标题 |
| H3 | **原理图 ≥ 1 张**（电路章 ≥ 2 张），SVG 放 `docs/assets/schematics/`，XML 必须可解析 | `scripts/check-content.ps1` |
| H4 | **每个出现的数值都能复算**：给公式、给代入过程、给结论 | 审核人逐条复算 |
| H5 | **自测题 ≥ 4 道**，全部用 `<details><summary>问题</summary>答案</details>` 折叠 | 计数 + 抽样打开 |
| H6 | **常见坑 ≥ 3 条**，必须是「现象 → 原因 → 解决」三元组 | 人工核对 |
| H7 | **来源 ≥ 3 条**，且能支撑具体结论（不接受"某厂官网首页"） | 人工核对 |
| H8 | **不得手写章号**（禁止"第 N 章""本章是全书第一章"）；跨章用相对链接 | 正则扫描 |
| H9 | 通过 `python packages/tooling/src/validate.py` 与离线构建（0 硬错误） | 门禁 |

## 2. 两套章型标准

同一个"11 模块"套在"欧姆定律"上会逼出废话。按**章型**分两套，顺序固定：

### 2.1 概念/原理章（concept）—— 8 个模块

适用：定律、基本概念、方法论（如欧姆定律、KCL/KVL、阻抗、谐振、麦克斯韦式思维工具）。

| 模块 | 必须回答的问题 |
|---|---|
| 1 设计动机 | 为什么工程师必须懂它？不懂会在哪里摔跤？ |
| 2 定义与直观 | 一句话定义 + 物理图像/类比 + 一张示意图 |
| 3 定量关系 | 公式、推导要点、**每个符号与单位**、适用条件与失效边界 |
| 4 典型计算 | ≥2 个完整算例，含代入过程与验算 |
| 5 工程含义 | 数量级、什么时候会违反假设、对选型/布线的实际影响 |
| 6 常见坑 | ≥3 条「现象 → 原因 → 解决」 |
| 7 自测题 | ≥4 道，覆盖概念/计算/排故 |
| 8 参考资料 | ≥3 条，具体到文档章节 |

### 2.2 电路/器件章（circuit）—— 11 个模块

适用：具体电路、器件、典型应用（如反相放大器、Buck、光耦驱动）。

| 模块 | 必须回答的问题 | 反例 |
|---|---|---|
| 1 设计动机 | 什么场景需要它？不做会怎样？ | 只说"很重要" |
| 2 原理图 | 元件标号、节点、电流方向、极性是否清楚？ | 图与正文对不上 |
| 3 静态分析（DC） | 电容开路/电感短路下的直流工作点、偏置 | 直接跳结论 |
| 4 动态分析（AC/瞬态） | 传递函数（结论）、频响/波形、时间常数 | 只给公式不解释符号 |
| 5 环路/稳定性 | 相位裕度、补偿方向、什么情况下自激 | 张冠李戴 |
| 6 元件取值与权衡 | 数量级、为什么这个量级、边界在哪 | 只写"取 10k" |
| 7 完整设计示例 | 从需求到验算走完整一遍，含最终数值 | 缺验算 |
| 8 仿真与实验 | 能照着做的步骤；命令/参数完整；预期结果 | 命令不能跑 |
| 9 常见坑 | 现象 → 原因 → 解决 | 只有结论没有现象 |
| 10 自测题 | 覆盖概念、计算、排故三类 | 全是名词解释 |
| 11 参考资料 | 具体到文档章节/应用笔记编号 | 只写厂商名 |

**判定章型**：有具体电路拓扑与元件取值的 → circuit；讲定律/概念/方法的 → concept。拿不准就问主审核。

## 3. 写作硬规矩

1. **数字优先**：能用算式就不用形容词。"远大于"要给出倍数或量级。
2. **符号先定义后使用**：公式后必须有一段解释每个符号与单位。
3. **单位统一 SI**：mA/kΩ/µF 可以，但同一个式子里不混用；温度写 °C，功率因数写 cos φ。
4. **绝对化表述禁止**：不写"绝对安全""一定不会""唯一办法"。凡涉及安全（市电、高压、电池、ESD、焊接），必须写清适用前提与失效条件。
5. **不编造数据**：器件参数以数据手册为准，写型号；查不到就写"典型量级，实测为准"，不要造具体数字。
6. **五类容器**：`motivation / analogy / example / pitfall / advanced` 按语义使用，不滥用 `tip` 等规范外类型。
7. **公式**：行内 `$...$`，块级 `$$...$$`；块级公式必须前后有空行。
8. **图表**：ECharts 用 ````echarts 围栏，JSON 必须可解析；图中数据必须与正文数值一致。
9. **链接**：章内 `[文字](#锚点)`；跨章 `../<篇>/<文件>.md`；外部链接给完整 URL。
10. **不要重写已有正确内容**：加深章节时保留原结构合理的部分，只补正确的扩展与删改错误。

## 4. 审核流程（主审核执行）

1. **结构门禁**：`python packages/tooling/src/validate.py`（0 硬错误）+ 脚本统计（字数/图/题/坑/来源）。
2. **数字复算**：逐条抽查 ≥ 60% 的数值结论，用计算器/脚本复算；错的必须给出正确值。
3. **技术判断**：涉及安全、器件极限、时序、标准的结论，逐条核对适用条件与出处；无法确认的标"待专业复核"，不得当作已确认。
4. **一致性**：与同篇其他章节的符号、术语、口径是否一致（如"运放/运算放大器"、"噪声增益"用法）。
5. **渲染**：离线单文件真实浏览器复测——`.katex-error = 0`、图片缺失 = 0、ECharts 全部画出。
6. **判决**：通过 / 退回（附具体到行的修改要求）。退回的必须重做，不接受"小问题放过"。

## 5. 图表与配图要求

- 原理图：`viewBox` 必填、不写死 `width/height`、文本用 `&amp;`/`&lt;` 转义、`role="img"` + `<title>`。
- 波形图：ECharts，必须标注坐标轴物理量与单位；示例数据要与正文公式一致（审核时抽一组点代入验证）。
- 示意图（流程/结构）：可用 SVG，风格与现有 `schematic-library.svg` 一致。

## 6. 分批与验收

- 每批 **≤ 4 章**，便于逐章审核；一批全过再开下一批。
- 每批完成后必须：门禁通过 → 内容指纹重新冻结（`pnpm freeze:<app>`）→ 我逐章审核 → 合入 `main` → 部署。
- 任何一章不达标，整批不合入。

## 7. 与"遗留问题"的关系

工程遗留问题（ECharts 包体、导入 merge、存储降级、离线锚点）与内容制作并行推进，但**互不阻塞**：
内容批次只依赖 §1 的门禁，工程改动不得让门禁变红；工程改动若影响渲染，必须在内容批次验收前修复并复测。
