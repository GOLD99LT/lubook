# ADR-0004 · 双形态共用 manifest 对账（Python 离线零依赖保留）

- 状态：Accepted（已落地，P0/P1/P2）
- 日期：2026-10-14
- 关联：ARCHITECTURE §3、§6、§14.1；[ADR-0002](ADR-0002.md)

## 上下文（Context）

手册长期提供两种形态：

1. **在线 VitePress 站**（交互、搜索、ECharts、学习功能）；
2. **离线单文件 HTML**（一个 6MB 自包含文件，无网络、无依赖即可看全 140 章）。

离线构建、四质检、素材抓取均为 Python 脚本。重构时需要保证两种形态渲染的是**同一份内容**，且离线版仍可在只装 Python 标准库的环境里构建。

## 决策（Decision）

- **保留 Python 工具链，不把离线/质检重写为 Node**（ARCHITECTURE §14.1）；脚本平移到 `packages/tooling/src/`，vendor/templates 随迁，新增 `paths_util.py` 做 repo-root 发现与参数化（`--app/--src/--out/--vendor`，默认等价 handbook）。
- 单一内容清单由 `@hw/content-core`（TS）生成；`packages/tooling/src/freeze_manifest.py`（纯标准库）保留同口径实现，二者**逐字一致**（`parity.ts` 做 deep-compare）。
- 离线构建 `build_single_html.py` 新增 `--manifest <content-manifest.json>`：构建后按章节数 / id 序列 / 标题序列 / 本地图片引用数 / revision 对账，不一致打印 `[MISMATCH]` 并非零退出；缺 manifest 仅告警、维持自解析。
- 仓库根 `run_quality.py` 聚合：manifest 一致性 + 路由/指纹快照比对、`validate`、`scan_math`、`scan_grounds`、`scan_svg_order`，任一项失败即非零。
- 离线 vendor（KaTeX/ECharts/字体）继续自托管，离线构建不触网。

## 备选方案（Alternatives）

- 用 Node 统一离线构建：技术上可行，但会破坏「仅 Python 标准库即可出离线包」的既有零依赖承诺，且要重写大量已验证逻辑，本期否决（仅允许非阻塞 POC，backlog B1）。
- 离线不做对账：可能与在线内容漂移而无人察觉，否决。

## 后果（Consequences）

- TS 与 Python 各有一份内容解析器，改解析口径必须**两边同改并跑 parity**，否则快照/对账失败。
- CI 与 `pnpm verify` 同时跑在线构建、模板构建、learning 单测、run_quality、离线 `--manifest` 对账，任一不过即红。
- 离线版始终零第三方 Python 依赖。历史上 `merge_sources.py` 用过 PyYAML，该脚本已于 2026-10-22 删除（生成输入丢失，且不在构建路径上）。
- 冻结基线（迁移前）与迁后指纹一致：140 章 / 418 图引用 / 411 SVG / 247 接地 / 141 路由 / revision `sha256-4c8521761e575941`。
