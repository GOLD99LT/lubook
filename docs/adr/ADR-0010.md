# ADR-0010：客户端包体预算与 ECharts 按需加载

- 状态：Accepted
- 日期：2026-10-22
- 相关：ADR-0001（技术栈）、ADR-0007（离线与在线两条交付路径）

## 背景

主题包 `@lubook/theme` 在 `components/EChart.vue` 里静态 `import * as echarts from 'echarts'`。
ECharts 全量约 1.0 MB（gzip ≈ 340 KB），于是：

- **门户首页**（只有卡片链接，一张图表都没有）也要下载整个图表库；
- **只有纯文字的章节**同样要下载；
- 140 章的站点，任何一次首屏都是"先付 1 MB 再说话"。

这不是"慢一点"的问题：门户是读者第一次接触产品的页面，首屏 JS 直接决定它要不要等。
离线单文件（另一条交付路径）本来就内联，不受影响。

## 决策

1. **ECharts 只在真正需要绘制时加载**：`EChart.vue` 改为 `await import('echarts')`，
   首次 `onMounted` 触发时动态导入，模块级缓存复用。
2. **动态导入必须处理竞态**：`import()` 是异步的，期间组件可能已卸载，落地前要重新校验
   `unmounted` 与 `el.value`；卸载标志用 `unmounted` 布尔量，避免对已 dispose 的实例操作。
3. **包体预算**（构建产物，实测于 2026-10-22）：

   | chunk | 改前 | 改后 |
   |---|---|---|
   | `theme.*.js`（每页都加载） | ≈1.15 MB | **113 KB** |
   | ECharts 独立 chunk | （在 theme 内） | 1.04 MB，**仅图表页加载** |
   | 门户 `theme.*.js` | ≈1.09 MB | **58.7 KB** |
   | 门户是否产出 ECharts chunk | 是（在 theme 内） | **否**（门户无图表，整块不产出） |

   规则：**任何进入"每页都加载"的 chunk 的依赖，必须能被 100 KB 量级解释**；
   超过的必须按需加载或给出理由。
4. **不引入图表按需注册**（`echarts/core` + 手工 `use()`）。当前 93 个图表用到的图元类型分散，
   手工注册的收益（再省约 40%）不值得维护成本与"新图表类型没注册就白屏"的风险。
   若将来图表类型收敛到 3 种以内，再重新评估。

## 后果

- 门户与纯文字章节少下载约 1 MB（gzip ≈ 340 KB）；图表页多一次网络往返，但图表本来就要等 JS。
- 图表渲染从"同步"变成"异步"：首屏会先出现空容器再绘制。已验证：图表页 `canvas` 正常出现，
  KaTeX 61 条 0 错误，学习面板正常水合。
- 新增约束：**EChart 组件不得被 SSR 路径静态依赖**（当前只在 `onMounted` 内使用，符合）。

## 验证

- `pnpm verify:all` 退出 0（构建 + 质检 0 失败 + 离线对账 + parser parity + learning 130 passed）。
- 部署包形态实测：`theme.*.js` 113 KB；`index.BzBQJFYZ.js`（ECharts）1.04 MB，由 theme 动态引用。
- 门户构建产物中不存在 ECharts chunk。
- 真实浏览器（`/lubook/hardware/opamp/inverting-amplifier.html`）：`canvas` = 1，公式 0 错误。
