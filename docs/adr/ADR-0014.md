# ADR-0014：P4 立项——嵌入式软件手册（MCU）与嵌入式 Linux 手册

- 状态：Accepted
- 日期：2026-10-24
- 相关：ARCHITECTURE §12（P4/P5）、ADR-0006（门户拓扑）、ADR-0013（双站部署）、
  `docs/DEVELOPMENT-STANDARD.md`

## 背景

ARCHITECTURE v3 把 `apps/embedded` 与 `apps/embedded-linux` 列为 P4/P5，长期只有计划没有内容；
门户卡片刻意以 `available: false` 占位。AGENTS.md §2.5 规定"未立项不做实际内容"。

2026-10-24 用户明确授权：**全面推进两个新分册的内容制作与审查，本地跑通且审查通过后再确认上线**。
这构成立项条件，且同时给出了"先本地闭环、再由用户确认上线"的验收口径。

## 决策

1. **立项 P4 的两个分册**（门户 slug 已存在，不改 URL）：
   - `apps/embedded`（@lubook/embedded），题名《嵌入式软件手册（MCU）》；
   - `apps/embedded-linux`（@lubook/embedded-linux），题名《嵌入式 Linux 手册》。
2. **完全复用既有工程形态**：`@lubook/shared-config` + `@lubook/theme` + `@lubook/content-core` +
   `@lubook/learning`，配置只改 `appId/title/partRegistry/nav`，不新增运行时依赖。
3. **篇结构**（各 6 篇，篇号即 frontmatter 的 `part`）：
   - embedded：基础 / Cortex-M 与外设 / 通信接口 / RTOS 与并发 / 存储启动与升级 / 工程实践与量产
   - embedded-linux：系统与构建 / 内核与驱动 / 用户空间与调试 / 硬件接口与板级支持 / 可靠性与升级 / 板级实战
4. **流程按 `docs/DEVELOPMENT-STANDARD.md`**：分批生产（3~6 章）→ 复算审查 → 机械门禁 →
   本地跑通 → 用户确认后再上线。未确认前门户卡片保持 `available: false`。
5. **工具适配**（本轮已改，保证可复用）：
   - `validate.py`：目录→篇号映射查不到时，改用"本章在 SUMMARY 的第几篇"判定，
     新分册无需改工具；
   - `scan_svg_order.py`：`assets/schematics` 不存在时视为 0 张，不再崩溃。

## 后果

- 两个分册进入 `verify:all` 的自动遍历（`apps/*` 自动发现），尚未接入 CI 部署矩阵的判断
  （CI 用 `apps/*` 枚举，会自动包含；上线前需确认部署拓扑仍成立）。
- 门户卡片在两个分册通过审查并部署后改为 `available: true`——**这一步等用户确认**。
- 不引入新依赖、不改 URL 规则、不改学习数据结构（`appId` 天然隔离 localStorage 键）。
