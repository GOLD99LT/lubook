# ADR-0009 · 内容指纹覆盖 SVG 字节 + 快照基线不被静默覆盖

- 状态：**Accepted（2026-10-22）**
- 日期：2026-10-22
- 关联：[ADR-0004](ADR-0004.md)（双形态共用 manifest 对账）、[ADR-0002](ADR-0002.md)（路径即 id）

## 上下文（Context）

两处内容完整性缺口，都会让"门禁全绿"与"内容真的没变"脱钩：

1. **指纹不含图形字节。** `freeze_manifest.py` 的 `overallChecksum` 只由章节 `.md` 的 checksum 汇总，`svgCount` 只是计数。把一张原理图里电阻的数值改掉、或换掉标注文字，只要文件数不变，`revision`、指纹与快照都不变——`run_quality` 依然 PASS。硬件分册有 411 张 SVG，约占内容资产的一半，等于这一半不在门禁视野内。

2. **快照基线会被自动覆盖。** `write_outputs()` 无条件重写 `tests/<app>.*.snapshot.json`，而 `pnpm verify:all` 与 CI 的 content-gate 都会调用它。于是"内容改了"这件事在门禁跑完后就变成了"基线也改了"，永远对得上。基线本应是**需要人工确认的发布契约**，不能由构建脚本自己改写。

## 决策（Decision）

### 1. 指纹新增 `assetsChecksum`

- 计算口径：`apps/<app>/docs/assets/**` 下所有文件，按相对路径排序后逐个求哈希（文本先按 LF 归一，与 `.md` 口径一致；无法解码的按原始字节），再对 `"路径\t哈希"` 行拼接求 sha256，取前 16 位加 `sha256-` 前缀。
- 写入 `tests/<app>.manifest.snapshot.json` 的 `assetsChecksum` 字段，随快照一起受门禁保护。
- **`revision` 的派生方式不变**（仍只由章节 checksum 决定）。理由：`revision` 会写进学习数据导出信封（ADR-0007 §1），把图形字节塞进去会让"内容 revision"在纯排版/绘图微调时抖动，反而降低这个字段的可读性。图形完整性由 `assetsChecksum` 单独承担。

### 2. 快照基线只能由显式动作更新

`freeze_manifest.py` 的行为改为：

| 情况 | 行为 |
|---|---|
| 快照不存在 | 直接生成（新分册引导） |
| 快照与当前内容一致 | 不写文件（工作区保持干净） |
| 快照与当前内容不一致 | **拒绝覆盖**，打印差异与下一步，退出码 2 |
| 带 `--accept` | 更新基线（等价于"我确认这次内容变更是有意的"） |

- `.generated/<app>-content-manifest.json` 仍每次写：它是构建中间产物（离线构建与 parser parity 都要用），不是基线。
- `package.json` 的 `freeze:<app>` 带 `--accept`——这是"确认基线变更"的显式命令。
- `verify_all.py` 把 freeze 的退出码 2 翻译成 `baseline` 失败，并提示 `pnpm freeze:<app>`。

## 验收（Verification）

- 内容未变：`run_quality` PASS，快照零改写，`git status` 干净。
- 改一张 SVG 的 `font-size`（不增删文件）：
  - `run_quality` → `[FAIL] manifest/fingerprint 比对`，退出 1；
  - `freeze_manifest` → `[baseline] 快照与当前内容不一致，未覆盖`，退出 2；
  - 还原文图与执行 `--accept` 后 → 恢复 PASS。
- `pnpm verify:all` 退出 0。

## 影响（Consequences）

- 快照多一个字段；旧快照缺该字段时会被判为不一致，需要一次 `--accept` 迁移（本次已随内容勘误一并完成）。
- 日常流程多一步：改内容后先 `pnpm freeze:<app>` 确认基线，再 `pnpm verify:all`。这是有意的摩擦——基线变更应当被看见。
- 仍未覆盖：`assets/` 之外的二进制（如将来引入图片/字体）与 `sources.list.yaml`；若引入，按同一口径扩展。
