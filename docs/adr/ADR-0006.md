# ADR-0006 · 品牌重命名为「路书 Lubook」与多 app 门户拓扑

- 状态：**Proposed（方案待用户核实；执行通过后转 Accepted）**
- 日期：2026-10-21
- 关联：[NAMING.md](../NAMING.md)、[ADR-0001](ADR-0001.md)、[ADR-0003](ADR-0003.md)、[ADR-0005](ADR-0005.md)、[ARCHITECTURE.md §9](../../ARCHITECTURE.md)、[EMBEDDED_PLAN.md](../../EMBEDDED_PLAN.md)、REQUIREMENTS 附录 A（B16）

## 上下文（Context）

- 项目从单一《硬件工程师手册》扩展为作者**个人多领域知识手册合集**：硬件、嵌入式软件（MCU）、嵌入式 Linux，以及未来更多领域。
- 旧命名全部绑定"硬件"：仓库 `hardware-handbook`、pnpm scope `@hw/*`、学习键前缀 `hh`/`hb`、硬件 `appId='handbook'`、根 base `/hardware-handbook/`。
- 品牌已拍板为**「路书 Lubook」（路先生知识手册）**，需要一个中性、可扩展、内部对称的多 app 命名与"门户占根、分册居子路径"的部署拓扑。
- 命名冲突核查通过（见 NAMING §8）：无商标/知名产品冲突；`lubook.com` 为停放页；`lubook.dev/.io` 等可注册；npm scope `@lubook` 干净。

## 决策（Decision）

### 1. 品牌与对外标识

- 品牌：路书 Lubook；仓库 `GOLD99LT/lubook`（由 `hardware-handbook` 改名）；本地工程根目录 `lubook`；根包 `lubook-monorepo`。
- GitHub Pages：`https://gold99lt.github.io/lubook/`；Cloudflare 项目改名 `lubook`，镜像 `https://lubook.pages.dev/`。

### 2. pnpm scope 与框架命名

- `@hw/*` → `@lubook/*`（所有包及全部 import 同步替换）。
- 根包：`hardware-handbook-monorepo` → `lubook-monorepo`。
- 框架工厂/CLI 用通用"book"词（不绑品牌、不绑领域）：
  - `defineHwConfig` → `defineBookConfig`；
  - `createHwTheme` → `createBookTheme`；
  - content-core CLI bin：`hw-manifest` → `book-manifest`。

### 3. 硬件分册改名（内容零改动）

- `apps/handbook` → `apps/hardware`（用 `git mv` 保留历史）；包 `@hw/handbook` → `@lubook/hardware`；`appId` `handbook` → `hardware`。
- 中文书名保留《硬件工程师手册》；URL 子路径 `/lubook/hardware/`。
- 140 章 md + 411 张 SVG 仅随目录 `git mv`，**内容一字不改**；归一化 LF 后内容指纹（revision）须与改名前逐字一致。

### 4. 新建极简门户 `apps/portal`（占根）

- 由 `templates/site-template` 生成：`appId='portal'`、标题「路书」、副标题「路先生知识手册」、base `/lubook/`。
- 首页极简：品牌标题 + 各分册卡片（首批 `hardware` 已可用；`embedded`/`embedded-linux` 显示"即将上线"占位）。
- 卡片配置分两类（在门户 `content.config.ts` 集中声明）：
  - **内部分册**：`{ type:'internal', slug, title, desc, icon }`，链接到 `/lubook/<slug>/`；
  - **外部站点**：`{ type:'external', title, desc, url, icon }`，新标签页打开（未来聚合其他网站；iframe 嵌入列为门户增强，不在本期）。
- 卡片图标统一用与 logo 同风格的内联 SVG 线性图标，无 emoji。

### 5. 多 app 工具链 / CI / 部署一次参数化

> 与品牌重命名合并实施（都改同一批 package.json、CI、部署、根脚本），避免后续再改一遍。

- **base 由环境变量派生**：每个 app 的 `config.mts` 不再写死 base，统一读 `VP_BASE`：
  - 门户 base = `VP_BASE`；分册 base = `VP_BASE + '<slug>/'`。
  - GitHub Pages：`VP_BASE='/lubook/'`；Cloudflare：`VP_BASE='/'`（两平台分别构建，沿用现状）。
- **新增 bundle 组装脚本** `packages/tooling/build_pages_bundle.py`：
  - 按 `VP_BASE` 构建门户与各分册；把门户 dist 放输出根，每个分册 dist 复制到 `<staging>/<slug>/`，产出一个可整体上传的站点目录。
  - 门户根 `index.html` 即路书首页；分册位于 `/lubook/<slug>/`（Pages）或 `/<slug>/`（CF）。
- **run_quality.py**：`--app/--src/--out/--snapshot-prefix`；每个分册独立 `tests/<app>.routes.snapshot.json`、`tests/<app>.manifest.snapshot.json`。
- **build_single_html.py**：按分册 `--manifest` 构建，输出 `dist/<app>.html`。
- **根 package.json**：为每个 app 提供 `gen:<app>/dev:<app>/build:<app>/offline:<app>`；`verify` 升级为遍历 `apps/*` 的 `verify:all`（各 app 构建 + 全量质检 + 全量离线 + learning 单测）。
- **quality.yml**：改为多 app 矩阵（`pnpm -r --filter ./apps/* run build` + 各 app 质检/离线/快照 + learning 单测）。
- **deploy-docs.yml**：构建并组装 bundle（`VP_BASE='/lubook/'`），统一 `upload-pages-artifact` 该 bundle；部署后对门户与各分册做 HTTP smoke。
- **deploy-cloudflare.yml**：`VP_BASE='/'` 构建并组装 bundle，`wrangler pages deploy --project-name=lubook`。

### 6. 学习数据键迁移（进度不丢）

- 新键：`lubook.v1.<slug>.learning`（如 `lubook.v1.hardware.learning`、`lubook.v1.embedded.learning`）。
- 硬件分册的历史数据有两个来源，需一并迁移：
  - 最早 `hh.v1.learning`（无 appId）；
  - 现行 `hb.v1.handbook.learning`（旧 appId `handbook`）。
- 实现：`@lubook/learning` 的仓储初始化支持 per-app 声明 `legacyKeys`；硬件分册在 `content.config.ts` 传入 `legacyKeys:['hh.v1.learning','hb.v1.handbook.learning']`，新 app 默认无旧键。
- 迁移**保留旧键不删除**（与 ADR-0003 一致），schemaVersion 不变；合并/冲突以最新 `updatedAt` 为准。

### 7. 域名

- 本期仅用免费 `github.io` / `pages.dev`；自定义域名 `lubook.dev`（备选 `lubook.io`）登记为 backlog **B16**，后续单独立项（注册、DNS、Pages/Cloudflare 自定义域、HTTPS）。

## 执行顺序（在分支 `refactor/brand-lubook`，基于当前 main）

- **0. 回滚点**：main 打 tag `pre-brand`；切 `refactor/brand-lubook`。
- **A. 本地改名**：根包/scope/工厂/CLI；`apps/handbook→apps/hardware`（appId/base/包名）；`templates/site-template` 同步。
- **B. 多 app 地基**：`VP_BASE` 派生、`build_pages_bundle.py`、run_quality/离线/快照参数化、根脚本与 CI。
- **C. 极简门户**：`apps/portal` 与分册卡片配置。
- **D. 学习数据**：`legacyKeys` 多源迁移 + 单测。
- **E. 本地验证**：`pnpm verify:all` 全绿；门户 + 硬件 桌面/移动截图；浏览器注入旧键实测迁移；离线 `dist/hardware.html` 对账。
- **F. 文档**：更新 NAMING/ARCHITECTURE/PLAYBOOK/README/CHANGELOG/AGENTS（本 ADR 转 Accepted）。
- **G. 自审**：全量自检后请用户核实；核实通过再执行 GitHub 侧动作。

## GitHub 侧（核实后，用户操作或明确授权）

1. 仓库 Settings → Rename：`hardware-handbook` → `lubook`（本地 `git remote set-url` 更新；GitHub 自动重定向旧 clone/push 地址）。
2. Settings → Pages：确认 Source 为 **GitHub Actions**；项目站路径随仓库名变为 `/lubook/`。
3. Cloudflare：新建/改名项目 `lubook`，确认 `lubook.pages.dev` 可用；更新 Secrets（`CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`）；旧 `hardware-handbook` 项目可保留或停用。
4. 旧链接 `/hardware-handbook/*`：因仓库改名 + 路径重排，个人项目**不做复杂 301**（上线不久、外链少）；待 B16 自定义域名后用固定路径彻底解耦。

## 回滚（Rollback）

- tag `pre-brand`；分支未合并可随时放弃；合并后异常可 revert 合并提交或回 `pre-brand` 重部署。
- 学习数据迁移保留旧键，回退不丢；内容仅 rename，可完整还原。

## 验收（Verification）

- `pnpm install --frozen-lockfile` 成功；`pnpm verify:all` 全绿。
- 门户 `/lubook/` 200、硬件 `/lubook/hardware/` 200（含首页与代表章）；移动端无横向溢出、无 emoji。
- 硬件 140 章 / 418 图 / 411 SVG，归一化 LF 后指纹与改名前一致（manifest 快照对账）。
- 离线 `dist/hardware.html` 140 章、对账一致。
- 浏览器注入 `hh.v1.learning` 与 `hb.v1.handbook.learning`，刷新后写入 `lubook.v1.hardware.learning`，进度/收藏/笔记完整保留。
- 全站无 `hardware-handbook`/`@hw`/`hb.` 残留（标题、Logo 角标、URL、键）。

## 本期不做（Consequences / 边界）

- 不注册/购买域名（B16，后续）。
- 不写 `embedded`/`embedded-linux` 内容（地基就绪后 P4 下一个任务开工）。
- 不做旧 URL 的 301 重定向、不做 iframe 嵌入外部站（门户增强）。
- 不实现 ADR-0005 的单 artifact 双发 / release.json（仍按两平台分别构建）。
