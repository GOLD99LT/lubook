# 嵌入式软件全景：从寄存器到 RTOS

> 本章是全书导读：说明这本手册解决什么问题、怎么读、与其他分册的关系。
> 具体章节的定量结论与来源在各章正文内给出。

## 这本手册要解决什么问题

嵌入式软件最常见的困境不是"不会写代码"，而是**不知道硬件此刻在做什么**：
外设寄存器写对了没有、中断为什么没进、DMA 为什么搬错半包、RTOS 里为什么偶尔丢一帧。
本手册按"硬件行为 → 寄存器语义 → 驱动结构 → 系统调度"的顺序组织，
每一章都给出可直接对照数据手册的寄存器位、时序图和可复算的时序数字。

## 学习路径

| 阶段 | 内容 | 产出 |
|---|---|---|
| 第一篇 | 工具链、内存模型、启动流程 | 能独立把裸机工程跑起来、能看 map 文件定位问题 |
| 第二篇 | Cortex-M 内核与外设 | 能写不依赖 HAL 的 GPIO/中断/定时器驱动 |
| 第三篇 | 通信接口 | 能用示波器/逻辑分析仪定位时序问题 |
| 第四篇 | RTOS | 能设计任务划分、优先级与同步策略 |
| 第五篇 | 存储与升级 | 能做 bootloader 与 OTA 升级 |
| 第六篇 | 工程实践 | 能做低功耗、可靠性与量产测试 |

## 与其他分册的关系

硬件部分（电源、信号完整性、EMC）见同站的《硬件工程师手册》分册；
本手册只讨论**软件如何正确驱动硬件**，以及软件侧能看到的现象与排查手段。

## 自测

<details><summary>为什么先学内存模型和启动流程，而不是直接点灯？</summary>
因为点灯成功只能证明"某一条路径通了"。一旦进入中断、DMA、Cache、多任务，
出问题的往往不是外设配置，而是启动时没有初始化时钟/向量表/栈，或内存布局与链接脚本不符。
先建立这两块的地图，后面每个现象才能定位到具体一层。
</details>

<details><summary>裸机和 RTOS 的调试手段有什么本质区别？</summary>
裸机可以靠断点和大循环定位；RTOS 下断点会改变时序、掩盖竞态，
必须依赖 trace、计数器和临界区分析。这也是第四篇单独成篇的原因。
</details>
